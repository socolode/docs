# Socolode Docusaurus 文档编辑规则

本 Skill 记录了 Socolode 项目 Docusaurus 文档的所有编辑规范和习惯，确保文档编辑的一致性和可维护性。

## 1. 项目结构

### 文档目录
```
d:\socolode-docs\
├── docs/                                    # 英文主文档（defaultLocale: en）
│   ├── intro.md
│   └── quick-start/
│       ├── _category_.json
│       ├── users/
│       │   ├── _category_.json
│       │   └── *.mdx
│       └── developers/
│           ├── _category_.json
│           └── *.mdx
├── i18n/
│   └── zh-CN/
│       ├── docusaurus-plugin-content-docs/
│       │   ├── current/                     # 中文翻译文档（结构与 docs/ 完全一致）
│       │   │   └── quick-start/
│       │   │       ├── _category_.json
│       │   │       ├── users/
│       │   │       │   ├── _category_.json
│       │   │       │   └── *.mdx
│       │   │       └── developers/
│       │   │           ├── _category_.json
│       │   │           └── *.mdx
│       │   └── current.json                 # 侧栏标签翻译
│       ├── docusaurus-theme-classic/
│       │   ├── footer.json
│       │   └── navbar.json
│       └── code.json
├── static/
│   ├── img/                                 # 图片资源
│   └── files/                               # 文件资源
├── sidebars.ts                              # 侧栏配置
└── docusaurus.config.ts                     # Docusaurus 配置
```

### 关键规则
- **文件结构必须匹配**：`docs/` 和 `i18n/zh-CN/docusaurus-plugin-content-docs/current/` 的目录结构、文件名、扩展名必须完全一致
- **先中文后英文**：在 `i18n/zh-CN/` 下编写中文文档，完成后**默认**同步到英文 `docs/` 对应文件
- **同步到英文为默认行为（无需询问）**：编辑完中文文档后，**必须自动执行 `sync-to-en`**，将对应英文 `docs/` 文件同步更新，**不需要再问用户**「是否同步到英文」。始终保持中英文一致
- **配置文件**：侧栏配置在 `sidebars.ts`，翻译标签在 `current.json`
- **触发关键词**：当用户说「同步到英文」「翻译文档」「sync-to-en」「翻译成英文」时，执行翻译同步流程；但**默认情况**下编辑中文文档后应直接同步英文，无需等待该关键词
- **SEO/GEO 规范**：创建或编辑文档时必须遵循 [seo-geo-rules.md](./seo-geo-rules.md) 中的 SEO 和 GEO 优化规范

## 2. 文件命名规范

### 规则
- 使用**小写英文** + **连字符**分隔单词
- 只允许：英文字母、数字、连字符 `-`
- 禁止：中文、空格、下划线、特殊字符

### 示例
✅ 正确：`what-is-light-painting.mdx`
✅ 正确：`camera-settings-tutorial.mdx`
❌ 错误：`What-Is-Light-Painting.mdx`（大写）
❌ 错误：`光绘入门.mdx`（中文）
❌ 错误：`what_is_light_painting.mdx`（下划线）

## 3. 链接规则（重要）

### 内部链接格式
```markdown
[链接文本](./target-file.mdx)           # 同目录
[链接文本](../folder/target-file.mdx)    # 跨目录
```

### 核心规则
1. **必须使用相对路径**：使用 `./` 或 `../` 开头，**禁止**使用绝对路径 `/docs/...`
2. **必须包含 `.mdx` 扩展名**：为了 Obsidian 兼容
3. **不使用 URL 编码**：保持文件名原样

### 为什么不能用绝对路径？
- `/docs/xxx` 会始终指向英文版本，导致中文页面跳转到英文
- 相对路径会自动根据当前语言解析

### 完整示例
```markdown
# 在 quick-start/users/beginner-faq.mdx 中链接同目录文件
[相机参数设置教程](./camera-settings-tutorial.mdx)

# 在 quick-start/users/beginner-faq.mdx 中链接跨目录文件
[开发者快速开始](../developers/5-minute-quick-start.mdx)

# 错误示例 ❌
[相机参数设置教程](/docs/quick-start/users/camera-settings-tutorial)  # 绝对路径 + 无扩展名
[相机参数设置教程](/docs/quick-start/users/camera-settings-tutorial.mdx)  # 绝对路径
```

## 4. 图片规则

### 存储位置
- **图片默认要放到文章目录下的 `assets/`**（即 mdx 同级目录的 `assets/`，如 `docs/.../apps-play/assets/`），中英文两侧都要放，引用用相对路径 `./assets/filename.png`
- 全局共用图片存放在 `static/img/` 目录
- 文件名遵循文件命名规范（小写英文 + 连字符）

### 引用格式
```markdown
![描述文本](/img/image-name.jpg)
```

### 示例
```markdown
![光绘示例](/img/light-painting-example.jpg)
![相机参数设置界面](/img/camera-settings-ui.png)
```

### 图片命名建议
- 使用描述性名称：`light-painting-example.jpg` 而非 `photo1.jpg`
- 按内容命名：`camera-settings-guide.png` 而非 `screenshot.png`

### 图片 SEO 规范
- **必须包含 alt 文本**：描述图片内容，包含关键词
- **OG 图片尺寸**：1200x630 像素（1.91:1 比例）
- **产品图片**：800x800+ 像素，JPG 格式
- **装饰性图片**：使用空 alt `![](/img/decorative.png)`
- 详细规范见 [seo-geo-rules.md](./seo-geo-rules.md) 图片 SEO 规范章节

## 5. 侧栏配置

### 侧栏自动生成
项目使用 `autogenerated` 模式，侧栏基于文件系统自动生成：
```typescript
// sidebars.ts
const sidebars: SidebarsConfig = {
  docsSidebar: [{type: 'autogenerated', dirName: '.'}],
};
```

### 侧栏分类
通过 `_category_.json` 控制分类名称和顺序：
```json
{
  "label": "分类名称",
  "position": 1
}
```

### 侧栏标签翻译
在 `i18n/zh-CN/docusaurus-plugin-content-docs/current.json` 中配置翻译：
```json
{
  "sidebar.docsSidebar.category.Quick Start": {
    "message": "快速开始",
    "description": "The label for category 'Quick Start' in sidebar 'docsSidebar'"
  }
}
```

### 添加新分类的步骤
1. 在 `docs/` 和 `i18n/zh-CN/.../current/` 下创建对应的目录
2. 创建 `_category_.json` 设置 label 和 position
3. 在 `current.json` 中添加对应的中文翻译条目

## 6. Frontmatter 格式

### MDX 文件头部
```markdown
---
sidebar_label: "页面名称"
sidebar_position: 1
title: "SEO 优化标题 - Socolode 分类名"
description: "150字以内的精炼描述，包含核心关键词"
keywords: ["关键词1", "关键词2", "关键词3"]
image: "/img/og-image.png"
---

# 页面标题

内容...
```

### 常用 frontmatter 字段
- `sidebar_label`: 侧栏中显示的名称（可选，默认使用 H1 标题）
- `sidebar_position`: 在侧栏中的排序位置
- `slug`: 自定义 URL 路径（可选）
- `title`: SEO 优化的页面标题（50-60 字符，包含关键词）
- `description`: 页面描述（140-160 字符，用于搜索结果摘要）
- `keywords`: 关键词数组（3-8 个，按重要性排序）
- `image`: 社交分享图片路径（1200x630，JPG/PNG）

### SEO/GEO 字段详细规范
详见 [seo-geo-rules.md](./seo-geo-rules.md) 中的 Frontmatter SEO 规范章节。

## 8. 新增文档流程

### 标准工作流：先中文 → 后英文（含 SEO/GEO 优化）

#### 步骤一：创建中文文档（含 SEO/GEO 优化）
1. 在 `i18n/zh-CN/docusaurus-plugin-content-docs/current/` 对应目录下创建 `.mdx` 文件
2. 使用中文编写内容
3. **添加 SEO/GEO Frontmatter**：`title`、`description`、`keywords`、`image`（详见 seo-geo-rules.md）
4. **GEO 内容优化**：第一句为定义优先句式、事实密度达标（原文内容包含 FAQ 的保留，不必去掉）
5. **添加 JSON-LD Schema**：在 `<head>` 中添加结构化数据标记（详见 seo-geo-rules.md）
6. 使用相对路径 + `.mdx` 扩展名链接内部文件
7. 如果是新分类，添加 `_category_.json` 和 `current.json` 翻译

#### 步骤二：翻译同步（sync-to-en，默认自动执行）
> **默认行为**：编辑完中文文档后**必须自动执行**同步到英文，**无需用户询问**。用户主动说「同步到英文」「sync-to-en」可视为确认，但不应等待。

执行以下操作：
1. 读取对应的中文文档
2. 将内容翻译为英文（保持 Markdown 格式和结构）
3. **翻译 SEO/GEO 字段**：title、description、keywords 独立翻译为英文
4. **翻译 GEO 内容**：定义句式、FAQ（原文已有的保留并翻译）、Schema inLanguage 更新为 "en"
5. 在 `docs/` 下创建对应的英文版本文件（相同路径和文件名）
6. 同步所有链接、图片引用等
7. 如果有新分类，同步 `_category_.json` 和侧栏配置

#### 步骤三：SEO/GEO 验证
- [ ] 中英文页面的 title 唯一且包含关键词
- [ ] description 长度合规且包含价值主张
- [ ] JSON-LD Schema 标记正确
- [ ] 第一句为定义优先句式
- [ ] 原文包含的 FAQ 部分已保留并翻译
- [ ] 图片包含 alt 文本

### 添加图片
1. 将图片放入 `static/img/` 目录
2. 使用规范的文件名（小写英文 + 连字符）
3. 在文档中通过 `/img/filename` 引用
4. 中文和英文文档共用同一图片路径
5. 必须包含描述性 alt 文本

## 9. 翻译同步流程（sync-to-en）

### 触发条件
> **默认自动**：编辑完中文文档后直接执行同步，无需用户明确要求。以下关键词出现时也触发（可视为用户确认）：
- 「同步到英文」
- 「翻译文档」
- 「sync-to-en」
- 「翻译成英文」
- 「同步英文版」

### 同步规则

#### 1. 文件同步
- 源文件：`i18n/zh-CN/docusaurus-plugin-content-docs/current/**/*.mdx`
- 目标文件：`docs/**/*.mdx`（相同相对路径和文件名）
- 如果目标文件不存在 → 创建新文件
- 如果目标文件已存在 → 覆盖更新内容

#### 2. 翻译要求
- 保持原文的 Markdown 结构（标题层级、代码块、表格、列表等）
- 保持所有 frontmatter 字段
- 翻译所有中文文本为英文
- 代码块内容**不翻译**（保持原样）
- 链接文本翻译，但链接路径保持不变
- 图片路径保持不变

#### 3. 侧栏/导航同步
- `_category_.json`：翻译 `label` 字段为英文
- `current.json`：不需要修改（它是中文翻译配置）
- 如果新增了分类，需要同时更新 `docs/` 和 `i18n/zh-CN/` 下的 `_category_.json`

#### 4. 链接处理
```markdown
# 中文原文
[相机参数设置教程](./camera-settings-tutorial.mdx)

# 英文译文
[Camera Settings Tutorial](./camera-settings-tutorial.mdx)
```
- 链接文本翻译
- 链接路径保持不变（相对路径 + `.mdx`）

#### 5. Frontmatter 处理
```markdown
# 中文原文
---
sidebar_label: "相机参数设置"
sidebar_position: 2
title: "相机参数设置教程 - Socolode 摄影指南"
description: "详细了解如何正确设置相机参数，包括曝光、白平衡、ISO 等核心设置。"
keywords: ["相机参数", "摄影教程", "Socolode", "曝光设置"]
image: "/img/camera-settings-guide.jpg"
---

# 英文译文
---
sidebar_label: "Camera Settings"
sidebar_position: 2
title: "Camera Settings Tutorial - Socolode Photography Guide"
description: "Learn how to properly configure camera settings including exposure, white balance, and ISO."
keywords: ["camera settings", "photography tutorial", "Socolode", "exposure settings"]
image: "/img/camera-settings-guide.jpg"
---
```
- `sidebar_label` 翻译
- `sidebar_position` 保持不变
- `title`、`description`、`keywords` 独立翻译为英文（不直接翻译，需针对英文搜索习惯优化）
- `image` 路径保持不变

### 同步检查清单
- [ ] 文件名与中文版本完全一致（除了路径前缀）
- [ ] 目录结构与中文版本完全一致
- [ ] frontmatter 已翻译（sidebar_label、title、description、keywords）
- [ ] 所有链接文本已翻译
- [ ] 所有链接路径正确（相对路径 + `.mdx`）
- [ ] 代码块保持原样
- [ ] 图片引用路径正确
- [ ] `_category_.json` 的 label 已翻译
- [ ] SEO 字段完整：title、description、keywords、image
- [ ] GEO 内容已同步：定义句式、FAQ（原文已有的保留并翻译）、JSON-LD Schema
- [ ] Schema 的 inLanguage 更新为 "en"
- [ ] 本地预览正常显示（`npm start` 英文模式）

## 10. Obsidian 兼容说明
